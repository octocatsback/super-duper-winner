# Security Policy

## Supported versions

Security updates are provided for the current `main` branch.

| Version | Supported          |
| ------- | ------------------ |
| `main`  | :white_check_mark: |
| older   | :x:                |

## Reporting a vulnerability

Please **do not** open a public GitHub issue for security reports.

Report vulnerabilities privately using one of these channels:

1. **GitHub private vulnerability reporting**  
   Open a private advisory at  
   https://github.com/octocatsback/super-duper-winner/security/advisories/new
2. **Email**  
   Send details to `octocatsback@outlook.com` with the subject  
   `SECURITY: super-duper-winner`.

Include as much of the following as you can:

- A description of the issue and its impact
- Steps to reproduce, or a proof of concept
- Affected versions, commits, or files
- Any suggested remediation

## What to expect

- You will receive an acknowledgement within **3 business days**.
- We will assess the report and follow up with next steps, a request for more information, or a decision that the report is out of scope.
- If the report is accepted, we will work on a fix and coordinate disclosure with you.
- If the report is declined, we will explain why.

Please give us a reasonable window to investigate and ship a fix before any public disclosure.

## Scope

In scope:

- Vulnerabilities in this repository's source, build, or published artifacts
- Exposure of secrets, credentials, or private data through this project

Out of scope:

- Issues that require physical access to a developer's machine
- Reports that depend on outdated or unsupported versions
- Social engineering against project maintainers
